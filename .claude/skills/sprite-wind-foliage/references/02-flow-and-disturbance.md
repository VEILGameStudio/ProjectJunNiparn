# 02 — Flow map ลม + ระบบ disturbance (วัดจากคลิป)

## 1. การเข้ารหัสสี (encoding)

| ช่อง | ความหมาย | 0.0 | 0.5 | 1.0 |
|---|---|---|---|---|
| R | เลื่อนแนวนอน | ซ้ายสุด | ไม่ขยับ | ขวาสุด |
| G | เลื่อนแนวตั้ง | ขึ้นสุด | ไม่ขยับ | **ลง**สุด (GameMaker แกน y ชี้ลง) |
| B | ไม่ได้ใช้ใน noise ลม | | | |

- สี neutral ที่วัดได้ในคลิป: **RGB ≈ (115, 114, 0)** — คือ R = G ≈ 0.5 หลังวิดีโอบีบช่วงสี ไม่ใช่ (128,128) เป๊ะ
- ⚠ **Unity: แกน UV y ชี้ขึ้น** ถ้ายก texture ของ GameMaker มาใช้ตรง ๆ ต้องกลับเครื่องหมาย G ไม่งั้นใบไม้จะปลิวขึ้นแทนลง
- offset จริง = `(rg − 0.5) × 2 × amplitude` แล้ว **ปัดเป็นพิกเซลเต็ม** (pixel art ต้องไม่มีครึ่งพิกเซล — ในคลิปพิกเซลยังเป็นสี่เหลี่ยมคมทุกเฟรม)
- ทิศ: ปิกเซลที่ "ขยับไปทางขวา" หมายถึง **อ่าน texture จากทางซ้าย** → `uv_sample = uv − offset`

## 2. Noise ลม — ลักษณะที่วัดได้

| สิ่งที่วัด | ค่า | วิธีวัด |
|---|---|---|
| ค่าสีในช่วงโชว์ texture (12–18 วิ) | R 102–196 (เฉลี่ย ~160), G 19–124 (เฉลี่ย ~65) | percentile 5–95 ทั้งกรอบ |
| ⇒ ทิศเฉลี่ย | **เอนขวา + ยกขึ้นเล็กน้อย** (R เกิน neutral, G ต่ำกว่า neutral) | ลมพัดจากซ้าย ใบโดนยกขึ้น |
| ขนาดลาย (spatial scale) | **ใหญ่กว่าต้นไม้** — ทั้งกรอบเห็นแค่ 1–2 ก้อน gradient | ภาพ w02 |
| การเลื่อนเห็นได้ไหม | phase correlation ทุก 0.5 วิ ได้ shift ≈ 0 px | ลายใหญ่มาก เห็นเป็น "สีค่อย ๆ เปลี่ยน" มากกว่า "เลื่อน" |
| ความถี่หลักของการโยก | **0.17–0.22 Hz** (รอบละ ~5 วินาที) | FFT ของ flow เฉลี่ยทั้งพุ่ม, 5 ช่วงเวลา |
| โยกทั้งพุ่ม (peak-to-peak) | **1–3 art px** | Farneback flow หลังหักการแพนกล้องด้วยลำต้น |
| ขยับเฉพาะที่ (ไม่เท่ากันทั้งพุ่ม) | **rms 0.7 art px** ตอนลมอย่างเดียว | ส่วนที่เหลือหลังลบค่าเฉลี่ย |
| พิกเซลที่เปลี่ยนใน 0.5 วิ | ~14% ของกรอบ เกือบทั้งหมดอยู่ที่ **ขอบก้อนใบ** และขอบ silhouette | `img/w04-motion-diff.jpg` |

ข้อสังเกตสำคัญ: เมื่อ offset ≤ 1–2 px บน pixel art ส่วนกลางก้อนใบ (สีเดียวกัน) ดูเหมือนนิ่ง สิ่งที่ตาเห็นว่า "ใบไหว" คือ
**ขอบระหว่างเฉดสีที่ขยับทีละพิกเซล** ⇒ ใบไม้ที่วาดเฉดน้อย/ขอบน้อย จะดูไม่มีลมแม้ใส่ค่าเท่ากัน

### แปลงเป็นสัดส่วน (ใช้กับงานที่ไม่ใช่ pixel art ได้)

ต้นในคลิปกว้าง ~121 art px:
- ลมเฉพาะที่ rms 0.7 px ≈ **0.6% ของความกว้างพุ่ม**
- โยกทั้งพุ่ม 1–3 px ≈ **1–2.5%**
- ตัวละครดัน (ประมาณจากช่วง slime, p90 สูงขึ้น 0.5 px และพื้นที่สว่างใน heatmap) ≈ **3–5%** ในรัศมีราว 1.5 เท่าของตัวละคร

## 3. Texture disturbance (ตัวละครดันใบไม้)

- เป็น texture ขนาดเท่าพื้นที่ (world-space) สีพื้น neutral (เหลืองขี้ม้า) ทั้งแผ่น
- ตำแหน่งตัวละครมี **จุดนุ่ม ๆ** (soft radial blob) สีที่วัดได้ **(143, 73, 94)** = R สูง (ดันขวา) G ต่ำ (ดันขึ้น)
  ⇒ ตัวละครที่เคลื่อนไปทางขวาและกระโดด ดันใบไปทาง **ทิศที่ตัวละครเคลื่อน**
- ในภาพ 24–29 วิ จุดเปลี่ยนสี ชมพู → ฟ้า → เขียวตามทิศการเคลื่อนไหว และตามตัวละครไป ⇒ เขียนใหม่ทุกเฟรม ตามความเร็ว
- **ใช้ร่วมกับลมด้วยการบวก** (`noise + disturbance − 0.5`) แล้วจึงใช้เป็น offset
- "ระบบ disturbance ที่ทำไว้สัปดาห์ก่อน" — ใช้ร่วมกับพุ่มเล็ก (mini trees) ด้วย ⇒ ระบบเดียว ใช้ได้กับพืชทุกชนิดในฉาก

## 4. ทำไมถึงเป็น slime (เชิงเทคนิค)

offset ที่ได้เป็นฟังก์ชันเรียบของตำแหน่ง ⇒ พิกเซลติดกันเลื่อนต่างกันน้อยมาก ⇒ ทั้งพุ่มถูก **warp ต่อเนื่อง** เหมือนยางยืด
ในงานจริง ใบไม้เป็นกลุ่มแยกกัน แต่ละกลุ่มควร **เลื่อนทั้งก้อน** (rigid) และกลุ่มติดกันเลื่อน **ไม่เท่ากัน** (มีรอยต่อ)
ตอนลมเบา (≤1 px) ความต่อเนื่องไม่เห็น แต่ตอนตัวละครดัน 5–6 px ความเรียบโชว์ชัด → "slime"

ทางแก้ที่เป็นไปได้ (คลิปเลือกข้อ 1):

1. **แยกเป็นหลายชั้น** แต่ละชั้นรับแรงคนละเท่า → เกิดรอยต่อระหว่างชั้น (ดู `03-layering-fix.md`)
2. ทำ noise เป็น **ก้อน** (cell / Voronoi ที่แต่ละ cell ค่าคงที่) ให้ตรงกับก้อนใบที่วาด → ต้องวาด mask ให้ตรงกัน งานมากกว่า
3. ใส่ **id ของก้อนใบ** ลงช่อง B ของ sprite แล้วให้ offset คงที่ทั้งก้อน → แม่นที่สุด แต่ต้องวาด id map ทุกต้น
