# 02 — รูปแบบการวางด่าน

## 1. รูปแบบผังห้อง

| รูปแบบ | หน้าตา | เหมาะกับ | ระวัง |
|---|---|---|---|
| **เส้นตรง** | A → B → C | tutorial (บ้านยาย), ช่วงเล่าเรื่อง | ติดแล้วไม่มีทางอื่น |
| **Hub** | ห้องกลาง + ห้องรอบๆ 3–4 ห้อง | ด่าน "ใหญ่ 1 เล็ก 4": อันใหญ่อยู่ hub, อันเล็กในห้องรอบ | hub ต้องมี landmark ชัด และเป็นที่เห็นความคืบหน้า |
| **ห่วง (loop)** | A → B → C → กลับ A ด้วยทางลัด | ด่านที่ต้องย้อน | ทางลัดต้องเปิดจากฝั่งไกล (ประตูที่เปิดได้จากข้างใน) |
| **เพชร** | แยกออก 2–3 ทาง แล้วมารวมที่ประตูใหญ่ | puzzle ใหญ่ที่ต้องรวมของจากหลายที่ (P7 สัญลักษณ์ 4 ตัว) | ต้องบอกว่าเหลืออีกกี่ชิ้น |
| **ชั้นซ้อน (layered)** | ห้องเดิมเปลี่ยนสภาพหลัง puzzle (น้ำลด, แสงมา) | ดินแดนนาค (ระดับน้ำ), ครุฑ (หมอก) | ใช้ห้องซ้ำได้ ประหยัดอาร์ต แต่ต้องเปลี่ยนให้เห็นชัด |

ด่านส่วนใหญ่ของ ANODARD: **ทางเดิน SideView → hub ThreeQuarter → ห้องย่อย → กลับ hub → ทางเดิน SideView ไปด่านถัดไป**
ตรงกับ CLAUDE.md §1: ThreeQuarter = ห้อง puzzle, SideView = ทางเชื่อม + puzzle เล็ก + พาผู้เล่นไปตามทาง

## 2. หลักวางของ

1. **lock ตรงข้ามทางเข้า** — เดินเข้าห้องปุ๊บเห็นสิ่งที่ขวางเป็นอย่างแรก
2. **clue อยู่ระหว่างทางเข้ากับ lock หรือรอบๆ lock** — เดินไปหา lock แล้วผ่าน clue เอง
3. **key อยู่นอกทางตรง แต่มองเห็นจากทาง** — ให้รู้สึกว่า "หาเจอเอง" โดยไม่ต้องคลิกทุกพุ่มไม้
4. **ของที่ต้องใช้ข้ามห้อง** ให้ภวินพูดถึงตอนเห็นครั้งแรก ("กรรไกรในตู้นี่…อาจได้ใช้") — นี่คือ hint P2 ใน GDD
5. **ห้ามวางของจำเป็นในมุมที่ถูกบัง** (ThreeQuarter: มุมล่างจอที่มี sprite สูงอยู่ด้านหน้า, SideView: หลัง foreground lip)
6. **กลุ่ม clue ที่เป็นชุดเดียวกัน** (4 สัญลักษณ์ P1) วางห่างกันพอให้ต้องเดินสำรวจ แต่ในห้องเดียวกัน และหน้าตาเป็น "ชุด" เดียวกัน
7. **ของคลิกได้ห้องละ ~3–8 จุด** — น้อยไป = ไม่มีอะไรสำรวจ, มากไป = คลิกมั่ว (ค่าเริ่มต้นของทีม ไม่ใช่กฎ)

## 3. SideView vs ThreeQuarter ในการวางด่าน

| | `SideView` | `ThreeQuarter` |
|---|---|---|
| ผู้เล่นเดิน | ซ้าย–ขวา ลึกได้ ~3 หน่วย | ทั่วพื้น |
| ใส่ puzzle | เล็ก, อยู่บนระนาบเดิน, หนึ่งจุดต่อหนึ่งจอ | ใหญ่, หลายจุดในห้องเดียว |
| เล่าเรื่อง | ดีมาก (เดินผ่านวิว, ตัวละครเห็นชัด 23% ของจอ) | วางฉากเป็นไดโอรามา เห็นความสัมพันธ์ของของในห้อง |
| ห้าม | ซ่อนของหลัง foreground, puzzle ที่ต้องเดินเข้าลึก | ห้องใหญ่เกินจอโดยไม่มีเหตุ, ของสำคัญหลังกำแพงสูงด้านหน้า |

## 4. ขนาดห้องจากกล้อง (คำนวณจาก CLAUDE.md §7)

**ThreeQuarter** — orthographic size 5 → เห็นสูง 2×5 = **10 หน่วย** บนจอ, กว้าง 10 × 16/9 ≈ **17.8 หน่วย**
pitch 30° → ระยะพื้นตามแนวจอ = 10 / sin 30° = **20 หน่วย**; yaw 45° → ห้องสี่เหลี่ยมด้าน *s* กว้างบนจอ ≈ *s*·√2
ห้องเห็นทั้งห้อง: *s*·√2 ≤ 17.8 → *s* ≤ ~12.5; เผื่อผนัง/ขอบ → **พื้น ≤ ~11 × 11 หน่วย**
ห้องยาวกว่านั้น กล้องจะเลื่อน (CLAUDE.md: "loosely, so the whole room stays readable") — ถ้าห้องใหญ่กว่าจอ ต้องมีเหตุผล (เช่น ต้องการให้ค้นพบ)

**SideView** — FOV 19, ระยะ 20 → สูงที่ระนาบผู้เล่น = 2 × 20 × tan 9.5° ≈ **6.7 หน่วย**, กว้าง ≈ **11.9 หน่วย** (16:9)
หนึ่งจอ = ~12 หน่วยของทางเดิน; วาง "เหตุการณ์" (ของ, NPC, วิว) **ทุก 1–2 จอ** เพื่อไม่ให้ทางเดินว่าง
ความลึกเดินได้ ~3 หน่วย

**21:9** — จอกว้างเห็นข้างมากขึ้น: ผนังหลังกว้าง 36 (`setup-area` §3) ห้ามพึ่ง "ขอบจอ" ในการซ่อนของ

## 5. สัญลักษณ์แผนที่หยาบ ASCII

ใช้ใน level brief ให้ทุกคนอ่านแบบเดียวกัน หนึ่งช่อง ≈ 1 หน่วย (ประมาณ)

```
#  ผนัง / ขวางทาง          .  พื้นเดินได้
D  ประตูไปห้องอื่น (ZoneDoor/SceneLoader)      d  ประตูที่ล็อก (lock)
L  lock ของ puzzle         C  clue        K  key / ไอเทม
N  NPC                     P  จุดเกิดผู้เล่น  *  landmark
T  กับดัก/มอน (เป็น puzzle)  ~  น้ำ/ทางที่ยังผ่านไม่ได้  F  foreground ที่บังได้
```

ตัวอย่าง: ห้องพระบ้านยาย (ThreeQuarter, ไม่ใช่สเกลจริง)

```
#############
#C  * L   C #     * = โต๊ะหมู่บูชา (landmark)
#.  .....  .#     L = ตู้มีแม่กุญแจรหัส ตรงข้ามประตู
#C ....... C#     C = กรอบรูป / ปฏิทิน / ลิ้นชัก / นาฬิกา
#.  .....  .#
######D######     D = ประตูจากโถงทางเดิน (ผู้เล่นเข้าแล้วเห็น L ก่อน)
```
