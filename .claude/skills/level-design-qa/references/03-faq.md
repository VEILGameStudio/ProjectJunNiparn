# 03 — คำถามที่ถามบ่อย

ตอบตามรูปแบบโหมด C (คำตอบสั้น / เพราะ / ตัวอย่างในเกมเรา / ถ้าจะทำต่าง)

**ถ: เบาะแสควรอยู่ห้องเดียวกับประตูที่ล็อกไหม**
คำตอบสั้น: ด่านต้นๆ ใช่ ด่านหลังๆ แยกได้
เพราะ: ห้องเดียวกันผู้เล่นเทียบ clue กับ lock ได้ทันที คนละห้องต้องจำ ซึ่งยากขึ้นมาก
ตัวอย่าง: P1 ห้องพระ — 4 clue กับแม่กุญแจอยู่ห้องเดียวกัน
ถ้าจะทำต่าง: แยกห้องได้เมื่อ clue จำง่าย (สัญลักษณ์ 1 ตัว) หรือภวินพูดสรุปให้

**ถ: puzzle ควรเรียงตายตัว หรือให้เลือกทำก่อนหลังได้**
คำตอบสั้น: ให้มี 2–3 อันที่ทำได้พร้อมกัน
เพราะ: ติดอันหนึ่งไปทำอีกอันได้ ไม่ค้าง และรู้สึกว่าได้เลือก
ตัวอย่าง: ป่า — P3, P4, P5 ทำสลับได้ แล้วรวมเป็นทางไป P6 (ข้อเสนอ ยังไม่ล็อก)
ถ้าจะทำต่าง: tutorial (บ้านยาย) เรียงตายตัวได้ เพื่อสอนทีละอย่าง

**ถ: ห้อง ThreeQuarter ควรใหญ่แค่ไหน**
คำตอบสั้น: เห็นทั้งห้องในจอเดียว พื้นประมาณ ≤ 11 × 11 หน่วย
เพราะ: CLAUDE.md §1 ต้องการให้ห้อง puzzle อ่านออกทั้งห้อง กล้อง ortho size 5 เห็นได้ประมาณนี้ (คำนวณใน 02 §4)
ถ้าจะทำต่าง: ห้องใหญ่กว่าจอได้ถ้าตั้งใจให้ค้นพบ — แต่ lock หลักต้องเห็นจากทางเข้า

**ถ: อยากให้มุมกล้องห้องนี้ต่ำลงนิดนึง**
คำตอบสั้น: ทำไม่ได้ มีแค่สองมุมที่ล็อก
เพราะ: มุมใหม่ = preset ที่สาม ต้องวาดอาร์ตทุกชิ้นใหม่อีกชุด (CLAUDE.md §0.5)
ถ้าจะทำต่าง: เลือก SideView ถ้าต้องการมุมต่ำ; ถ้ายังอยากได้ → `design-change-proposal`

**ถ: puzzle ใหญ่ควรอยู่ต้นหรือท้ายด่าน**
คำตอบสั้น: lock อยู่ต้นด่าน (ให้เห็น), การแก้อยู่ท้ายด่าน
เพราะ: เห็นตั้งแต่ต้น = รู้เป้าหมาย; แก้ท้าย = ใช้ของจาก puzzle เล็กทั้งหมด
ตัวอย่าง: ป่า — ประตูกลไก P6 ควรเห็นตั้งแต่เข้าป่าชั้นนอก แม้จะแก้ได้ทีหลัง

**ถ: ต้องย้อนกลับไปห้องเก่าได้ไหม หรือปิดทางหลังผ่าน**
คำตอบสั้น: ในด่านเดียวกันให้ย้อนได้ ข้ามด่านแล้วปิดได้
เพราะ: ถ้าปิดทางในด่าน ผู้เล่นที่ลืมของจะค้างถาวร
ถ้าจะทำต่าง: ปิดได้เมื่อแน่ใจว่าไม่มีอะไรจำเป็นเหลือข้างหลัง (เช็กด้วยผังพึ่งพา)

**ถ: วางของคลิกได้กี่ชิ้นในห้องดี**
คำตอบสั้น: ~3–8 จุด
เพราะ: น้อยไปห้องดูตาย มากไปผู้เล่นคลิกทุกอย่างแทนการคิด
ถ้าจะทำต่าง: ห้องที่เป็น "ห้องค้นหา" มีได้มากขึ้น แต่ของประดับต้องดูต่างจากของคลิกได้ชัด (`level-readability`)

**ถ: มอนในด่านนี้ควรอยู่ตรงไหน**
คำตอบสั้น: เป็น lock ของ puzzle หนึ่งอัน — อยู่ตรงทางที่ผู้เล่นอยากไป
เพราะ: Oak กำหนดว่ามอนผ่านด้วย puzzle ไม่ใช่สู้ มันจึงทำหน้าที่เหมือนประตูที่มีนิสัย
ตัวอย่าง: (Oak) ใช้เทียนทำให้มันติด — ต้องเห็นนิสัย "ชอบแสง" ก่อนในที่ปลอดภัย
ดูเพิ่ม: `puzzle-design/references/04-monsters-and-traps.md`

**ถ: ทางเดิน SideView ยาวแค่ไหนดี**
คำตอบสั้น: 2–5 จอ (~25–60 หน่วย) และมีอะไรเกิดขึ้นทุก 1–2 จอ
เพราะ: หนึ่งจอ SideView ≈ 12 หน่วย; ทางเดินว่างยาวน่าเบื่อ สั้นไปไม่รู้สึกว่าเดินทาง
ตัวอย่าง: ป่า Test_Forest — ใส่วิว, NPC, puzzle เล็ก หรือของเก็บ ระหว่างทาง
(ค่าเริ่มต้นของทีม ไม่ใช่กฎใน CLAUDE.md)

**ถ: ผู้เล่นไม่รู้ว่าต้องไปทางไหน ทำยังไง**
คำตอบสั้น: ใช้แสง เส้นนำสายตา และ landmark ก่อนใช้ลูกศร
เพราะ: เกม storybook ควรนำทางด้วยฉาก ไม่ใช่ UI
ดูเพิ่ม: `level-readability` §นำสายตา
