# Level design Q&A — ถาม–ตอบเพื่อจัดวางด่าน puzzle

skill นี้มี 3 โหมด เลือกจากสิ่งที่ทีมพิมพ์มา

| ทีมพูดว่า | โหมด |
|---|---|
| "อยากออกแบบด่าน/ห้องใหม่", "ช่วยวางด่านหน่อย" | **A. สัมภาษณ์** — Claude ถาม ทีมตอบ ทีละรอบ จนได้ level brief |
| "ด่านนี้โอเคไหม", "ช่วยรีวิวด่าน" (มีฉาก/ภาพ/ผังมาแล้ว) | **B. รีวิว** — Claude ถามคำถามตรวจ แล้วสรุปจุดที่ต้องแก้ |
| คำถามเดี่ยว เช่น "เบาะแสควรอยู่ห้องเดียวกับประตูไหม" | **C. ตอบคำถาม** — ตอบจาก `references/03-faq.md` + เหตุผล + ตัวอย่างในเกมเรา |

แหล่งความจริง: puzzle/เรื่อง = GDD (`puzzle-design/references/01-puzzle-types.md`), ระบบ/กล้อง/สเกล = `CLAUDE.md`
คิด puzzle แต่ละอันด้วย `puzzle-design`; สร้างพื้นที่จริงด้วย `setup-area`; เช็กว่าอ่านง่ายด้วย `level-readability`

## กติกาการถาม (ทุกโหมด)

1. **ถามทีละรอบ รอบละไม่เกิน 3 คำถาม** — ทีมเป็นมือใหม่ ถามเยอะทีเดียวจะตอบไม่ครบ
2. **ทุกคำถามมีตัวเลือกให้** (ก/ข/ค + "อื่นๆ") และบอกว่า Claude แนะนำข้อไหนเพราะอะไร — คนตอบแค่ "ก" ก็ไปต่อได้
3. **บอกว่าถามเพื่ออะไร** หนึ่งบรรทัด ("ถามเพราะถ้าเบาะแสอยู่คนละห้อง ผู้เล่นต้องจำ")
4. **สรุปสิ่งที่ได้ก่อนขึ้นรอบใหม่** 2–3 บรรทัด ให้ทีมแก้ได้ถ้าเข้าใจผิด
5. **ไม่รู้ = ใช้ค่าแนะนำแล้วเขียนว่า "สมมติ"** อย่าค้างรอ — ทำเครื่องหมายไว้ให้ Oak/ทีมยืนยันทีหลัง
6. คำตอบที่ชนกฎล็อก (กล้องมุมใหม่, ระบบใหม่, เนื้อเรื่องใหม่) → หยุดเรื่องนั้น บอกเหตุผลสั้นๆ แล้วใช้ `design-change-proposal`
7. ภาษาไทยง่ายๆ เสมอ

## โหมด A — สัมภาษณ์ 5 รอบ

คำถามเต็มอยู่ใน `references/01-question-bank.md` เลือกมารอบละ ≤ 3 ข้อที่ยังไม่รู้คำตอบ

| รอบ | หัวข้อ | ต้องได้คำตอบ |
|---|---|---|
| 1 | **เรื่องและเป้าหมาย** | ด่านนี้อยู่ตรงไหนของเรื่อง, ผ่านแล้วได้อะไร, ผู้เล่นควรรู้สึกอะไร, สอนอะไรใหม่ |
| 2 | **puzzle และลำดับ** | puzzle ใหญ่ 1 + เล็ก ~4 คืออะไร (ใช้ GDD ถ้ามี), อันไหนปลดอันไหน, ไอเทมอะไรบ้าง |
| 3 | **พื้นที่** | กี่ห้อง/sub-area, แต่ละห้อง `ThreeQuarter` หรือ `SideView`, ต่อกันยังไง, ย้อนกลับได้ไหม |
| 4 | **วางของ** | lock อยู่ไหน, clue อยู่ไหน, key อยู่ไหน, ผู้เล่นเห็นอะไรก่อน, จุดสังเกต (landmark) |
| 5 | **จังหวะและความชัด** | พักตรงไหน, cutscene ตรงไหน, คำใบ้, ผู้เล่นจะรู้ได้ยังไงว่าทำครบ |

หลังรอบ 2: เขียนผังพึ่งพา JSON แล้วรัน
`python3 .claude/skills/puzzle-design/scripts/check_puzzle_chart.py <chart.json> --mermaid`
แจ้ง ERROR/WARN ให้ทีมในรอบถัดไปเป็นคำถาม ("ตอนนี้กรรไกรถูกใช้หมดก่อนประตูที่สองจะใช้ ให้ย้ายไปไหนดี ก/ข")

หลังรอบ 5: เขียน **level brief** ตาม `templates/level-brief.md` ประกอบด้วย
1. สรุปเรื่องและเป้าหมาย
2. ตาราง puzzle (ชื่อ, ขนาด, ชนิด, "อ๋อ", ห้อง)
3. ผัง Mermaid จากสคริปต์
4. **แผนที่หยาบ ASCII** ของแต่ละห้อง (ดูสัญลักษณ์ใน `references/02-layout-patterns.md` §5)
5. รายการ "สมมติ" ที่ยังต้องยืนยัน
6. งานต่อไป: skill ไหน ใครทำ (`puzzle-design` การ์ดต่อ puzzle, `setup-area`, `add-puzzle`, `add-item`, `add-dialogue`)

บันทึก brief ไว้ที่ `Docs/levels/<level-id>-brief.md` ถ้าทีมต้องการ (สร้างโฟลเดอร์ได้ ไม่ใช่ไฟล์ core)

## โหมด B — รีวิวด่านที่มีอยู่

1. ขอสิ่งที่มี: ภาพหน้าจอ (ทั้งสองกล้องถ้ามี), รายชื่อ puzzle, ฉากอยู่ไหนใน repo — อ่านอย่างเดียว ห้ามแก้ฉากคนอื่น
2. สร้างผังพึ่งพาจากสิ่งที่เห็น รันสคริปต์
3. ไล่ **คำถามรีวิว** ใน `references/01-question-bank.md` §6 — ข้อไหนตอบจากภาพได้ ตอบเอง ข้อไหนไม่รู้ ถามทีม (≤ 3 ต่อรอบ)
4. ภาพหน้าจอ → รัน `level-readability` (squint/contrast) ด้วย
5. สรุปเป็นตาราง: ปัญหา / ทำไมผู้เล่นจะติด / แก้ยังไง (เรียงจากร้ายแรงสุด: ค้างถาวร > หลง > งง > สวยน้อย)

## โหมด C — ตอบคำถามเดี่ยว

ตอบในรูปนี้ (ไทย, สั้น):
```
คำตอบสั้น: <หนึ่งประโยค>
เพราะ: <หลักการ + ผลต่อผู้เล่น>
ตัวอย่างในเกมเรา: <บ้านยาย / ป่า P3–P7>
ถ้าจะทำต่าง: <เงื่อนไขที่แบบอื่นถูก>
```
ถ้าคำถามจริงๆ คือ "ช่วยวางให้หน่อย" → เปลี่ยนเป็นโหมด A

## ตัวเลขกล้องที่ใช้คิดขนาดห้อง

คำนวณจากค่าที่ล็อกใน CLAUDE.md §7 (ไม่ต้องจำ ใช้ตอนตอบ "ห้องควรใหญ่แค่ไหน") — รายละเอียดใน `references/02-layout-patterns.md` §4

| | `ThreeQuarter` (ortho size 5, pitch 30°, yaw 45°) | `SideView` (FOV 19, ระยะ 20) |
|---|---|---|
| เห็นบนจอที่ระนาบผู้เล่น (16:9) | สูง 10 × กว้าง ~17.8 หน่วย; พื้นลึก ~20 หน่วยตามแนวจอ | สูง ~6.7 × กว้าง ~11.9 หน่วย |
| ห้องที่ "เห็นทั้งห้องในจอเดียว" | พื้นสี่เหลี่ยมประมาณ ≤ 11 × 11 หน่วย | ทางเดินยาวได้ กล้องตามซ้าย–ขวา ลึก ~3 หน่วย |
| ตัวภวิน | ~1.55 หน่วย | ~23% ของความสูงจอ |
