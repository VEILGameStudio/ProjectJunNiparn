# Puzzle design — วิธีคิด puzzle สำหรับ ANODARD

skill นี้คือ **การคิด** ไม่ใช่การเขียนโค้ด ผลลัพธ์คือ "การ์ด puzzle" (`templates/puzzle-card.md`)
พอการ์ดผ่านแล้วค่อยไป `add-puzzle` เพื่อสร้างจริงในเกม

แหล่งความจริง: เนื้อเรื่อง/ตัวละคร/puzzle 7 อันที่ออกแบบแล้ว = GDD (สรุปใน `references/01-puzzle-types.md`),
ระบบและสเกล = `CLAUDE.md` (§8 `PuzzleBase`, `MiniGameBase`, `HeldItemCheck`, `QuickTimeEvent`)

**เกมต้นแบบด้านความคิด (Oak เลือก):** Portal 2 = สอนกลไกด้วยฉาก หนึ่งห้องหนึ่งความคิดใหม่ ภาษาภาพที่ไม่โกหก;
ตระกูล Rusty Lake = puzzle ที่เล่าเรื่อง ห้องเล็กแน่น สัญลักษณ์ที่วนกลับมา — อ่าน `references/05-portal2-rusty-lake.md`
ทุกครั้งที่คิด puzzle ใหม่ (เอาแค่หลักคิด ห้ามลอกเนื้อหา)

> **ใครตัดสิน:** puzzle 1–7 ใน GDD อนุมัติแล้ว ปรับรายละเอียดได้
> puzzle ใหม่ที่ไม่มีใน GDD หรือแก้เนื้อเรื่อง = งานออกแบบเกม **Oak ตัดสิน** → ทำการ์ดให้ครบแล้วส่งให้ Oak ก่อนสร้าง

## หัวใจ 8 ข้อ

1. **puzzle หนึ่งอัน = "อ๋อ!" หนึ่งครั้ง** — เขียนให้ได้ในประโยคเดียวว่าผู้เล่นต้อง *เข้าใจอะไร* (ไม่ใช่ *กดอะไร*)
   ถ้าเขียนไม่ได้ แปลว่ายังไม่มี puzzle มีแต่ "งาน" (chore)
2. **กุญแจ–แม่กุญแจ–เบาะแส (Lock / Key / Clue)** — ทุก puzzle มี *สิ่งที่ขวาง* (lock), *สิ่งที่ปลด* (key: ไอเทม/รหัส/ลำดับ/การกระทำ)
   และ *เบาะแสที่บอกว่า key คืออะไร* (clue) ผู้เล่นต้อง **เห็น lock ก่อนได้ key** จะได้รู้ว่ากำลังหาอะไร
3. **ยุติธรรม = ทุกอย่างที่ต้องรู้อยู่ในเกม** — คำตอบอนุมานได้จากสิ่งที่เห็น/ได้ยิน/อ่านในเกมเท่านั้น
   ห้ามต้องเดา ห้ามต้องลองทุกแบบ (brute force) ห้ามต้องรู้นอกเกม (ยกเว้นที่ GDD ตั้งใจ เช่น P5 คำศัพท์อังกฤษ)
4. **สอน → ทดสอบ → บิด (teach → test → twist)** — กลไกใหม่โผล่ครั้งแรกแบบง่ายมากในที่ปลอดภัย,
   ครั้งต่อไปให้ใช้เอง, ครั้งที่สามบิดให้ใช้แบบที่ไม่เคยคิด แล้ว *เลิกใช้* ก่อนผู้เล่นเบื่อ
5. **puzzle ต้องเล่าเรื่อง** (สไตล์ Rusty Lake) — คำตอบมาจากโลก ตัวละคร และวัฒนธรรมหิมพานต์
   แก้เสร็จแล้วผู้เล่นได้รู้อะไรเพิ่มเกี่ยวกับดินแดน/ยาย/มณี ไม่ใช่ sudoku ที่แปะลงฉาก
6. **ด่านละ ~5 puzzle: ใหญ่ 1 เล็ก 4** (CLAUDE.md §8) — เล็กๆ ปลดกันเองหรือรวมกันปลดอันใหญ่ (`requiredPuzzleIds`)
   วาด **ผังพึ่งพา (dependency chart)** ทุกครั้ง — `references/02-dependency-chart.md`
7. **มอนสเตอร์และกับดัก = puzzle ไม่ใช่การต่อสู้** (Oak ตัดสิน 2026-11-05) — ศัตรูคือ lock ที่ขยับได้
   ผู้เล่นชนะด้วยการเข้าใจมัน ไม่ใช่ตีมัน — `references/04-monsters-and-traps.md`
8. **ติดได้ แต่ไม่ค้าง** — มีคำใบ้เป็นขั้น (NPC/พ่อหมอคราม/สมุดยาย/highlight เมื่อ idle) และ **ไม่มีทางทำให้เกมตัน**
   (ของใช้แล้วหมดต้องเป็นสิ่งสุดท้ายที่ puzzle ต้องการ — CLAUDE.md §8 CRITICAL) — `references/03-fairness-and-hints.md`

## Workflow: ได้โจทย์ "คิด puzzle ให้หน่อย"

1. **ตั้งต้นจากเรื่อง ไม่ใช่จากกลไก** — ถาม/ระบุ: อยู่ดินแดนไหน, ฉากไหนของเรื่อง, ผู้เล่นควรรู้สึกอะไร,
   ผ่านแล้วได้อะไร (เปิดทาง/ไอเทม/ความจริงข้อหนึ่ง) ใช้ธีมดินแดนจาก `references/01-puzzle-types.md` §3
2. **เขียน "อ๋อ" หนึ่งประโยค** — เช่น P1: "สัญลักษณ์บนของในห้องพระคือลำดับตัวเลข"
3. **เลือกชนิด puzzle** จากแคตตาล็อก `references/01-puzzle-types.md` §1 — ดูด้วยว่าด่านนี้มีชนิดนั้นแล้วหรือยัง (อย่าซ้ำติดกัน)
4. **ออกแบบ Lock / Key / Clue** — แต่ละ clue วางที่ไหน, ผู้เล่นเห็นมันก่อนหรือหลัง lock, มี clue ซ้อนสองทางไหม
   (clue ที่สำคัญควรมี 2 ทางให้เจอ เช่น ภาพ + บทพูด)
5. **วางในผังพึ่งพาของด่าน** — เขียน JSON ตาม `references/02-dependency-chart.md` แล้วรัน
   `python3 .claude/skills/puzzle-design/scripts/check_puzzle_chart.py <chart.json>`
   แก้ทุก ERROR และอ่าน WARN ทุกข้อ
6. **ตรวจความยุติธรรม** — checklist ใน `references/03-fairness-and-hints.md` §1 ทุกข้อ
7. **เขียนบันไดคำใบ้ 3 ขั้น** (กระซิบ → ชี้ → เกือบบอก) — `references/03-fairness-and-hints.md` §2
8. **จับคู่กับระบบที่มี** (ขั้นบันไดของ `add-puzzle`): Inspector อย่างเดียว? `HeldItemCheck`? `QuickTimeEvent`?
   หรือต้อง subclass `MiniGameBase`/`PuzzleBase` ใหม่ (Intern A)? ถ้าต้องการ Journal, combine ไอเทม,
   monster AI, pathfinding หรือแก้ core → เขียนลงการ์ดว่า "ติด hard stop" แล้วส่ง Oak
9. **ถาม 7 ข้อเร็ว** ใน `references/05-portal2-rusty-lake.md` §D
10. **กรอกการ์ด** `templates/puzzle-card.md` (ภาษาไทย) แล้ว **ทดสอบบนกระดาษ** — อธิบายให้คนที่ไม่รู้คำตอบฟังแค่สิ่งที่อยู่ในฉาก
   ถ้าเขาแก้ได้ในเวลาที่ตั้งไว้ และพูด "อ๋อ" ออกมา = ผ่าน
11. ส่งการ์ด → (Oak ถ้าเป็น puzzle ใหม่) → `add-puzzle`

## Workflow: "puzzle นี้ไม่สนุก / ผู้เล่นงง ช่วยดูหน่อย"

ไล่อาการตามตารางนี้ก่อนแก้อะไร

| อาการ | สาเหตุที่พบบ่อย | แก้ |
|---|---|---|
| ผู้เล่นไม่รู้ว่าต้องทำอะไร | ไม่เห็น lock หรือไม่รู้ว่า lock คือ lock | ย้าย lock ให้เห็นก่อน, ให้ภวินพูดถึงมัน (Mini dialogue), เพิ่ม feedback ตอนคลิกครั้งแรก |
| รู้ว่าต้องทำอะไรแต่ไม่รู้คำตอบ | clue อ่อน/ซ่อนเกิน/ไม่เชื่อมกับ lock | ทำ clue ให้ "หน้าตาเหมือน" lock (สัญลักษณ์/สี/รูปทรงเดียวกัน), เพิ่ม clue ทางที่สอง |
| รู้คำตอบแต่ทำไม่ได้ | UI/การควบคุมกวน | ลดขั้นตอนกด, เพิ่ม snap/เรืองเมื่อใกล้ถูก (แบบ P4) |
| ลองมั่วจนผ่าน | ตัวเลือกน้อย/ไม่มีราคาของการผิด | เพิ่มตัวเลือก หรือให้ผิดแล้ว reset ลำดับ (แบบ P3) — ไม่ใช่ลงโทษหนัก |
| ผ่านแล้วไม่รู้สึกอะไร | ไม่มี "อ๋อ" หรือไม่มีรางวัลทางเรื่อง | เพิ่ม payoff: cutscene สั้น, ยาย/พ่อหมอพูด, โลกเปลี่ยนให้เห็น |
| ติดค้างถาวร | ใช้ไอเทมหมดก่อนขั้นสุดท้าย / clue อยู่หลัง lock ที่มันเปิด | ตามกฎ §8 CRITICAL และสคริปต์ check_puzzle_chart |
