# 02 — ผังพึ่งพา puzzle (Puzzle Dependency Chart)

แนวคิดจาก Ron Gilbert (Monkey Island / Thimbleweed Park): วาดด่านเป็น **กราฟของ "ต้องมีสิ่งนี้ก่อนถึงจะทำสิ่งนั้นได้"**
อ่านจากล่าง (เป้าหมายของด่าน) ขึ้นบน (สิ่งที่ผู้เล่นทำได้ตั้งแต่ต้น)
ไม่ใช่แผนที่ ไม่ใช่ลำดับเรื่อง แต่บอกว่า **ผู้เล่นติดได้ตรงไหน และมีงานให้ทำกี่ทางพร้อมกัน**

## 1. ชนิดของโหนด

| type | ความหมาย | ตัวอย่าง |
|---|---|---|
| `start` | จุดเริ่มด่าน (มีอันเดียว) | เข้าบ้านยาย |
| `area` | พื้นที่ที่เข้าได้ (ห้อง, sub-area 1.1, camera zone) | ห้องพระ |
| `clue` | ข้อมูลที่ผู้เล่นต้องเห็น/ได้ยิน | ดอกไม้บนกรอบรูป = 1 |
| `item` | ของที่เก็บได้ | กรรไกร |
| `puzzle` | สิ่งที่ผู้เล่นต้องแก้ (มี puzzleId ในเกม) | แม่กุญแจรหัส |
| `door` | ทางที่เปิดเพราะ puzzle/ไอเทม | ประตูห้องนอน |
| `goal` | จบด่าน (มีอันเดียว) | เข้านอน → เหตุการณ์ถัดไป |

## 2. รูปแบบ JSON (สำหรับ `scripts/check_puzzle_chart.py`)

```json
{
  "level": "L1 Grandma house",
  "nodes": [
    {"id": "start", "type": "start", "label": "เข้าบ้านยาย"},
    {"id": "shrine", "type": "area", "label": "ห้องพระ", "requires": ["start"]},
    {"id": "clue_frame", "type": "clue", "label": "กรอบรูป ดอกไม้=1", "requires": ["shrine"], "in_area": "shrine"},
    {"id": "scissors", "type": "item", "label": "กรรไกร", "requires": ["start"], "in_area": "living"},
    {"id": "p2_tape", "type": "puzzle", "label": "ตัดเทปกล่องคุกกี้", "requires": ["p1_cabinet", "scissors"], "consumes": ["scissors"], "size": "small"},
    {"id": "goal", "type": "goal", "label": "เข้านอน", "requires": ["bedroom_door"]}
  ]
}
```

ฟิลด์:
- `requires` — โหนดที่ต้องเสร็จ/มีก่อน (AND ทั้งหมด) ถ้าต้องการ OR ให้ใช้ `requires_any: [[a,b],[c]]` = (a และ b) หรือ c
- `in_area` — clue/item อยู่ในพื้นที่ไหน (ใช้ตรวจว่า clue ไม่อยู่หลัง lock ที่มันเปิด)
- `consumes` — ไอเทมที่ puzzle นี้ใช้หมด (ตรวจกฎ CLAUDE.md §8: ใช้หมดต้องเป็นครั้งสุดท้ายที่ต้องใช้)
- `size` — `large` / `small` สำหรับ puzzle (ตรวจ "ใหญ่ 1 เล็ก ~4")
- `opens` — (ทางเลือก) สำหรับ clue: บอกว่า clue นี้ใช้กับ puzzle ไหน ตรวจว่า clue เข้าถึงได้โดยไม่ต้องผ่าน puzzle นั้น

## 3. สิ่งที่สคริปต์ตรวจ

| ระดับ | ตรวจ | ทำไม |
|---|---|---|
| ERROR | อ้างโหนดที่ไม่มี, วนลูป, start/goal ไม่ใช่อันเดียว | ผังพัง |
| ERROR | goal ไปไม่ถึง / โหนดที่ไปไม่ถึง | ด่านจบไม่ได้หรือมีของเกินที่ไม่มีวันเจอ |
| ERROR | clue ที่ `opens` puzzle X แต่ต้องแก้ X ก่อนถึงจะเห็น clue | ผู้เล่นค้างถาวร |
| ERROR | ไอเทมถูก `consumes` แล้วยังมีโหนดอื่นต้องใช้หลังจากนั้น | กฎ §8 CRITICAL: ของหมดก่อนใช้ครบ = ค้าง |
| WARN | puzzle ใหญ่ไม่ใช่ 1 หรือ puzzle รวมห่างจาก 5 มาก | สเกลตาม CLAUDE.md §8 |
| WARN | ช่วงที่มีงานทำได้แค่ 1 อย่างติดกันยาว (คอขวด) ≥ 3 ขั้น | ผู้เล่นติดอันเดียวแล้วไม่มีอะไรทำ |
| WARN | ไอเทมที่ไม่มีใครใช้ / clue ที่ไม่ได้ `opens` อะไร | ตัวหลอก (red herring) — ตั้งใจไหม? เกม cozy ควรมีน้อย |
| INFO | ความกว้างของผัง (จำนวนงานที่ทำได้พร้อมกันในแต่ละชั้น) | 2–3 ทางพร้อมกันกำลังดี ผู้เล่นติดอันหนึ่งไปทำอีกอันได้ |

## 4. รูปร่างผังที่ดี

```
        start
       /  |  \
     P-a P-b P-c        <- เปิดกว้าง: ทำได้หลายทาง ไม่ค้าง
       \  |  /
      P-ใหญ่            <- คอขวดตั้งใจ (puzzle ใหญ่ รวมผลจากเล็ก)
         |
        goal
```

- **เพชร (diamond)**: เปิดกว้างแล้วรวม = ดีที่สุดสำหรับด่าน "ใหญ่ 1 เล็ก 4"
- **เส้นตรงยาว**: ง่ายต่อการเล่าเรื่องแต่ติดแล้วไม่มีทางไป → ใช้แค่ในด่าน tutorial (บ้านยาย)
- **ต้นไม้หลายกิ่งไม่รวม**: ผู้เล่นหลงว่าทำครบหรือยัง → ต้องมีตัวบอกความคืบหน้า (เช่น ช่องมณีที่เรือง)

## 5. แปลงเป็นเกม

- ทุกโหนด `puzzle` = หนึ่ง `PuzzleBase` (หรือ `MiniGameBase`) ที่มี `puzzleId` ไม่ซ้ำ
- เส้น puzzle→puzzle = `requiredPuzzleIds`
- เส้น item→puzzle = `Required Item` / `HeldItemCheck`
- เส้น puzzle→door = wire `OnPuzzleCompleted` เข้ากับประตู (Intern B)
- โหนด `area` ที่ยังไม่ได้สร้าง = งานของ `setup-area`
