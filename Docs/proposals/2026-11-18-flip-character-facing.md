# ข้อเสนอเปลี่ยนดีไซน์: ทิศตัวละครกลับด้านเมื่อพลิกกล้อง
ผู้ขอ: nasrintohmi2004-dev   วันที่: 2026-11-18
อยากให้เกมเป็นแบบไหน: ในโถง SideView ที่ติ๊ก Allow Camera Flip เมื่อกด Q พลิกกล้อง ตัวละครที่ยืนหันหน้าเข้ากล้องอยู่ ต้องกลายเป็นเห็นด้านหลัง (ซ้าย/ขวาก็กลับด้านเช่นกัน) เพราะกล้องไปอยู่อีกฝั่งของตัวละคร ปัจจุบันตัวละครยังหันทางเดิมบนจอ
ติดกฎข้อไหน: CLAUDE.md §7 Facing ("PlayerAnimator คิดทิศจากทิศบนหน้าจอ") และ §7 Camera flip (ข้อความ "สไปรท์หมุนตามกล้อง ไม่ต้องวาดใหม่"); PlayerAnimator เป็นโค้ด core ของ Oak
ทำไมกฎนี้มีอยู่: ทิศบนหน้าจอทำให้ W/A/S/D และแถวอาร์ตตรงกับที่ผู้เล่นเห็นเสมอ การคิดทิศจากโลกจริงทำให้ตัวละครอาจ "เดินถอยหลัง" บนจอ
ทางเลือกที่ทำได้ตอนนี้: ไม่มี (ต้องแก้ PlayerAnimator) ระหว่างนี้ตัวละครคงทิศเดิมบนจอตามที่ Oak อนุมัติไว้ในประเด็น #44

ถ้า Oak อนุมัติ ต้องแก้อะไรบ้าง:
- ทางเลือก A (แนะนำ, เล็กสุด): ตอนพลิกกล้องครั้งเดียว กลับค่าทิศที่ถืออยู่ 180° (หน้า<->หลัง, ซ้าย<->ขวา) เฉพาะเมื่อพลิกจริง
  จากนั้นเมื่อผู้เล่นกดเดิน ทิศยังคิดจากทิศบนจอตามเดิม (กด W = หลัง เสมอ) ผลคือการเดินดูถูกทั้งสองฝั่ง ต่างแค่ท่ายืนตอนพลิก
  ไฟล์: PlayerAnimator.cs (อ่าน LevelSettings.IsFlipped / ฟัง OnCameraZoneChanged ตอน flip) + เทสต์ SnapTo... ที่ flipped และไม่ flipped
- ทางเลือก B (ตรงตามคำขอเต็ม): ทิศทั้งหมดคิดจากทิศในโลก เมื่อพลิกจะกลับทั้ง x และ y ตลอดเวลา
  ผลข้างเคียง: กด D ตัวละครเดินไปขวาบนจอ แต่ถูกวาดหันซ้าย (เดินถอยหลัง) ต้องให้ Oak ตัดสินว่ายอมรับไหม
- ทั้งสองทางใช้ได้เฉพาะ IsFlipped = true ส่วน ThreeQuarter, SideView ที่ไม่ติ๊ก และกล้องปกติ ใช้โค้ดเดิมเป๊ะ ไม่กระทบ
- อาร์ต: แถว 4 ทิศของ SideView (หน้า/หลัง/ขวา/ซ้าย) ใช้ได้เลย ไม่ต้องวาดใหม่ NPC ที่หันหาผู้เล่นต้องตรวจเพิ่ม
- เทสต์ EditMode: ไม่พลิก (ต้องเหมือนเดิม) และพลิก; ตรวจ save/load ตอนพลิกอยู่
- ต้องแก้ CLAUDE.md §7 Facing และ Camera flip ให้ตรงกับทางที่เลือก

ความเสี่ยง: ทางเลือก B ทำให้เดินถอยหลังบนจอ และกลับกับความเข้าใจ camera-relative; ทั้งสองทางแตะ PlayerAnimator ซึ่งเป็น core; ต้องตรวจ NPC และ animation อื่นที่อ่านทิศ
